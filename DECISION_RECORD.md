# AFTERCARE decision record

## Candidates considered

1. Dependency maintenance RPGF — web evidence + semantic consensus + native GEN.
2. Security patch continuity fund — web evidence + native GEN.
3. Documentation error-prevention fund — web evidence + semantic consensus.
4. Community moderation recovery fund — social evidence + semantic consensus.
5. Dataset preservation fund — web evidence + semantic consensus.
6. Infrastructure uptime aftercare — API evidence + native GEN.
7. Open-source incident counterfactuals — screenshots + semantic consensus.
8. Public research reproducibility fund — documents + semantic consensus.

The selected v1 is the constrained **maintenance claim** flow because it combines the clearest counterfactual, independently retrievable evidence, and a bounded payout category. It passes the gates: GenLayer replaces a trusted committee; claimants and funders can distrust one another; impact requires semantic judgement; the contract retrieves evidence; contributors can return for each round; and the slow assessment is separated from registration and funding.

## Self-audit

Candidates 1, 2, and 6 share the same maintenance pattern; they are distinct mainly by evidence type and affected resource. The chosen design uses web retrieval and native value, with semantic equivalence as the core capability. If web access did not exist, I would choose screenshot-backed documentation or incident evidence, but that would reduce freshness and breadth.

## Non-determinism budget

One assessment per claim. The only non-determinism is retrieving each frozen URL and comparing structured semantic conclusions. Verdict categories are bounded; payout logic remains deterministic and `insufficient_evidence` abstains.
